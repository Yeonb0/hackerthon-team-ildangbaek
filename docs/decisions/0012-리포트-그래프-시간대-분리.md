# 0012. 리포트 그래프 — 일자 대표값을 쓰지 않고 모닝·나이트를 각각 반환

- 상태: **제안**
- 날짜: 2026-08-11
- 담당: B(윤진)
- 관련: TBD-12(해소), REPORT-01, F-REPORT-01, ADR 0009

## 맥락

REPORT-01의 추이 그래프는 일자별로 점 하나를 그린다. 그런데 사용자는 하루에 최대 2건
(모닝·나이트)을 기록할 수 있어서, 두 건이 있는 날 무엇을 그릴지 정해야 했다.

기존 명세는 이를 **TBD-12**로 열어 두고 "나이트 우선, 없으면 모닝"을 제안으로 표시했다.
구현도 그대로 따라가 `ReportService.pickRepresentativePerDate`가 하루 2건 중 하나를 골랐다.
`docs/STATUS.md` 미해결 4번이 "확정 필요"로 남겨 둔 항목이다.

프론트엔드에서 이 규칙의 변경을 요청했다(`backend-requests-phase6.md` A1). 요지는 사용자가
**"낮에 바른 제품의 영향"과 "밤에 바른 제품의 영향"을 구분해서 보고 싶어 한다**는 것이다.
밤만/낮만 이어 보는 기능도 함께 검토 중이라고 밝혔다. 현재 응답 구조로는 두 슬롯을 구분할
방법이 아예 없다 — 서버가 이미 접어서 내려주기 때문이다.

## 결정

### 1. 대표값 규칙을 폐기한다

일자별 대표값을 산출하지 않는다. TBD-12는 "어떤 규칙을 쓸까"가 아니라 **"규칙 자체가 필요 없다"**로
닫는다.

### 2. `graph` 항목이 두 슬롯을 각각 싣는다

```
{ "date": "2026-08-01", "morningScore": 70, "nightScore": 73 }
```

기존의 `score` 필드는 **제거한다.** 남겨 두면 "대표값"의 정의가 다시 필요해져 TBD-12가 살아난다.

### 3. 결측 표현은 슬롯 단위로 확장한다

기록이 없는 슬롯은 `null`이다. 기존 BR 1("기록 없는 날짜를 0으로 계산하지 않는다")이 슬롯 단위로
그대로 적용된다.

| 상황 | `morningScore` | `nightScore` |
| --- | --- | --- |
| 두 슬롯 모두 기록 | 값 | 값 |
| 모닝만 기록 | 값 | `null` |
| 나이트만 기록 | `null` | 값 |
| 기록 없음 | `null` | `null` |

지표 값이 없는 기록(분석 미완료 등)도 해당 슬롯을 `null`로 둔다 — 결측과 같게 취급한다.

## 근거

1. **서버가 정보를 버리고 있었다.** 조회 쿼리는 원래 하루 2건을 모두 읽어 온다. 대표값 규칙은
   그중 하나를 **버리는** 로직이었다. 클라이언트가 두 슬롯을 원하는 이상 버릴 이유가 없다.
2. **비용이 늘지 않는다.** DB 스키마·쿼리·조회 횟수가 그대로다. `SkinRecord`에 `timeSlot`이 이미
   있어 추가 조회가 없다. 오히려 접는 로직이 사라져 서비스가 단순해진다.
3. **어떤 대표값 규칙도 근거가 없었다.** "나이트 우선"은 명세가 스스로 제안이라고 표시한 값이고,
   왜 나이트가 그날을 더 잘 대표하는지에 대한 논거가 없었다. 근거 없는 규칙을 확정하는 것보다
   규칙을 없애는 편이 정직하다.
4. **깨뜨리기 가장 싼 시점이다.** 프론트엔드는 아직 전부 목업 모드이고(`EXPO_PUBLIC_USE_MOCK=true`),
   REPORT-01을 실연동한 화면이 없다. 응답 구조 변경 요청을 프론트가 먼저 했으며, 조기 확정을
   요청했다.
5. **ADR 0009의 평균 규칙과 충돌하지 않는다.** 시차 분석은 여전히 하루 2건을 지표별 평균으로
   합친다. 목적이 다르기 때문이다 — 분석은 **날짜당 관측 하나**가 있어야 시차를 계산할 수 있지만,
   그래프는 사용자가 두 시간대를 눈으로 구분하는 화면이다. ADR 0009의 결정은 그대로 유효하며,
   다만 그 본문이 REPORT-01의 옛 규칙과 대비해 설명한 부분에 후속 주석을 달았다.

## 결과

- `ReportGraphPointResponse`가 `{date, morningScore, nightScore}`로 바뀐다. **`score`는 제거된다 —
  기존 응답을 소비하던 코드는 깨진다.**
- `ReportService.pickRepresentativePerDate`가 삭제되고 `groupScoresByDateAndSlot`으로 대체된다.
- `ReportServiceTest`의 "나이트 우선" 테스트가 "두 슬롯 각각 반환"으로 교체되고, 한쪽만 기록한
  날을 검증하는 테스트가 추가된다.
- `api_명세서.md` REPORT-01의 응답 예시 · BR 1 · BR 2 · TBD-12 블록 · TBD 요약표가 갱신된다.
- `기능명세서.md` F-REPORT-01 BR 3과 13장 TBD 표가 갱신된다.
- **프론트엔드에 알려야 한다.** 목업(`api/mock/`)도 같은 구조로 맞춰야 하며, 그래프 컴포넌트가
  슬롯 두 개를 그리도록 바뀌어야 한다.
- **REPORT-03(일자별 리포트 조회)은 아직 미구현이다.** 구현 시 같은 원칙(접지 않는다)을 따를지
  그 시점에 확인해야 한다 — 화면 성격이 다르면 달라질 수 있다.
- 단일 선 그래프가 필요해지면 **클라이언트가** 두 값 중 하나를 고르거나 합친다. 서버는 더 이상
  그 판단을 하지 않는다.
