# 0026. 피부 지표 원시 측정값 보존 — SkinMetric에 raw_value·confidence·버전 추가

- 상태: **수락**
- 날짜: 2026-08-16
- 담당: B
- 관련: [ADR 0002](0002-피부-지표-체계.md) · [ADR 0008](0008-종합-점수-산출식.md) · [ADR 0020](0020-규칙-기반-로컬-비전-분석.md) · [ADR 0022](0022-openai-비전-2단계-점수-확정.md)

## 맥락

`SkinMetric.metric_value`는 0~100으로 정규화된 점수만 저장한다. 이 점수가 나온 원본 측정값
(`ai-server/app/metrics.py`가 CIELAB 색공간에서 실제로 계산하는 백분위·표준편차 값)은
`_to_score()` 호출 직후 버려지고, HTTP 응답에도 실리지 않았다 — DB 이전에 이미 유실됐다.

정규화 구간값(`REDNESS_RANGE` 등)은 ADR 0020이 명시한 대로 합성 이미지 실측 기반의 잠정치이며
"반드시 재조정해야 한다"고 문서화되어 있다. 재조정 시점에 과거 원시 측정값이 없으면, 새 기준으로
과거 사진들의 점수가 어떻게 달라졌을지 전혀 알 수 없다 — 재분석하려면 원본 이미지를 다시 돌려야
하고, 이미지가 없으면(재촬영 유도 등으로 폐기됐으면) 영구히 알 수 없다.

## 결정

**`SkinMetric`에 `raw_value`·`confidence`·`algorithm_version`·`normalization_version` 4개
컬럼을 추가하고, ai-server가 이 값을 실제로 산출할 때만 채운다.** 기존 컬럼·API 계약은 그대로
둔다.

```
사진 → ai-server 1차 분석(CIELAB) → raw 측정값 → _to_score() → 1차 점수
                                                              → (OpenAI 확정 성공 시) 최종 점수
raw 측정값 ─────────────────────────────────────────────────────┘ (변경 없이 그대로 저장)
```

### raw_value의 범위 — CIELAB 1차 측정값만

ADR 0022로 최종 저장되는 점수는 대부분 OpenAI Vision이 결정한다(클램핑 없음). OpenAI는 수치
측정값을 산출하지 않고 점수만 판단하므로, "raw_value → normalize() → score"가 **항상** 성립한다고
말할 수 없다 — OpenAI가 1차 점수와 동떨어진 값을 낼 수 있기 때문이다(ADR 0022 의도된 설계).

그래서 `raw_value`는 **1차(규칙 기반) 단계의 CIELAB 측정값**으로 한정한다. 이 값은 항상 존재하고,
공식이 명확하며(`app/metrics.py`의 각 `_metric` 함수), `algorithm_version`으로 버전을 추적할 수
있다. 최종 score가 OpenAI로 대체된 기록은 `raw_value`가 있어도 `score = normalize(raw_value)`가
아닐 수 있다는 것을 인지하고 써야 한다 — 이 괴리 자체가 "OpenAI가 1차 판단을 얼마나 신뢰했는가"의
근거 데이터가 된다.

### 각 지표의 raw_value 정의

| 지표 | raw_value 의미 | 단위/성질 | 현재 계산 위치 |
| --- | --- | --- | --- |
| REDNESS | 볼(cheeks) 영역 a*(적록축)의 상위 85 백분위 | CIELAB a* 값, 양수일수록 붉음 | `metrics._redness` |
| PIGMENTATION | 주변보다 어두운 정도(가우시안 블러 배경과의 명도차)의 상위 99.6 백분위 | CIELAB L 배경차, 양수일수록 반점 심함 | `metrics._pigmentation` |
| PORES | 피부 고주파 텍스처(원본−블러)의 표준편차 | CIELAB L 표준편차, 클수록 텍스처 강함(노이즈와 원리적으로 미분리) | `metrics._pores` |
| TROUBLE | (개인 기준선 대비 상대 붉기 × 국소 음영)의 상위 99.9 백분위 | 두 신호의 곱, 클수록 붉고 튀어나온 지점 존재 | `metrics._trouble` |

네 값 모두 "낮을수록 좋은 상태"이며 `_to_score()`가 부호를 뒤집어 "높을수록 좋은" 0~100 점수로
바꾼다(ADR 0002 방향성과 일치).

### confidence — 근거 있는 지표만

임의로 신뢰도를 만들지 않는다. 현재 실제 근거가 있는 지표는 **PORES 하나뿐**이다 —
`_PORES_NOISE_FLOOR`(카메라 노이즈·JPEG 아티팩트와 구분되지 않는 실측 구간)를 기준으로
`"LOW"`/`"NORMAL"`을 판정한다(ADR 0020). REDNESS·TROUBLE·PIGMENTATION은 이런 판정 근거가 없고,
OpenAI Vision도 신뢰도를 제공하지 않는다 — 이 세 지표는 `confidence`를 `NULL`로 둔다.

향후 신뢰도를 추가할 수 있는 근거 후보: 얼굴 검출 랜드마크 신뢰도, `preprocess.check_quality`의
화질 지표(선명도·노출), 피부 마스크 픽셀 수. 지금은 이 신호들을 신뢰도로 환산하는 근거가 없어
보류한다.

### algorithm_version / normalization_version — 상수 문자열로 최소 구현

`ai-server/app/metrics.py`에 `ALGORITHM_VERSION = "cielab-v1"`, `NORMALIZATION_VERSION =
"to-score-v1"` 상수를 두고 `compute()`가 그대로 응답에 싣는다. 재계산 엔진이나 버전별 분기 로직은
만들지 않는다 — 지금 필요한 것은 "이 raw_value가 어떤 코드로 만들어졌는지" 추적 가능성이지,
자동 재계산 기능이 아니다. `REDNESS_RANGE` 등 구간값이나 `_to_score` 공식이 바뀌면 이 상수도
반드시 함께 올린다.

### 응답 계약 — ai-server → Spring → DB만, 프론트 API는 그대로

- `ai-server` `/analyze` 응답에 `raw`(지표별 float) · `algorithm_version` · `normalization_version`
  필드를 추가한다. 기존 `scores`·`pores_reliability`는 그대로 둔다.
- Spring `SkinAnalysisResult`에 `rawValues`·`confidence`·`algorithmVersion`·`normalizationVersion`을
  추가한다. `LocalVisionSkinAnalysisClient`는 새 필드를 파싱하되, 없으면(구버전 응답) 빈 값으로
  두고 실패시키지 않는다 — rawValue는 보조 정보이지 필수 응답 계약이 아니다.
- `MockSkinAnalysisClient`는 근거가 없어 `SkinAnalysisResult.ofScoresOnly()`로 점수만 채운다.
- `SkinRecordWriter`가 `SkinMetric` 저장 시 네 컬럼을 함께 채운다.
- **프론트엔드 응답(`SkinScoresResponse`, `SkinRecordResponse`)은 변경하지 않는다.** rawValue는
  DB에만 저장하고 API로 내려주지 않는다 — 일반 사용자 화면에는 score·grade·summary·change 정도만
  필요하고, rawValue는 디버깅·향후 재정규화용 내부 데이터이기 때문이다. 필요해지면 관리자/디버그
  전용 엔드포인트를 별도로 만든다.

### 기존 데이터 마이그레이션

`ddl-auto: update`로 컬럼을 nullable 추가한다(Flyway/Liquibase 없음, DB 스키마 결정 참고).
기존에 저장된 `SkinMetric` 행은 `raw_value`가 전부 `NULL`로 남는다. **기존 score에서 raw_value를
역산하지 않는다** — 역산값은 실제 측정값이 아니므로 이 ADR의 원칙(raw_value는 실제 측정값이어야
한다)에 위배된다. 새로 분석되는 기록부터만 값이 채워진다.

## 근거

1. **지금이 가장 싼 시점이다.** 실사용 데이터가 아직 거의 없어 마이그레이션 부담이 없다.
2. **정규화 재조정이 예정된 변경이다.** ADR 0020이 이미 "실사용 데이터가 쌓이면 반드시
   재조정해야 한다"고 명시했다 — 그 시점에 원시 측정값이 없으면 재조정 근거 자체가 없다.
3. **기존 API·서비스 로직을 건드리지 않는다.** `totalScore` 산출(ADR 0008), `grade` 부재,
   프론트 응답 구조 모두 그대로다 — 변경 범위가 저장 계층과 그 계층으로 가는 데이터 통로로
   국한된다.

## 대안 검토

- **score만으로 재정규화 근사**: 기각. score는 `_to_score`가 구간값으로 정보를 압축한 결과라
  역함수가 존재해도 원본 분포를 복원할 수 없다(클리핑 구간의 정보 손실).
- **모든 지표에 confidence를 즉시 추가**: 기각. PORES 외에는 실제 근거가 없어 임의로 채우면
  이 ADR이 스스로 금지하는 "근거 없는 값 생성"이 된다.
- **score를 OpenAI 판단이 아니라 규칙 기반으로 되돌려 raw→score 관계를 항상 성립시키기**:
  기각. ADR 0022의 범위를 벗어난다 — 이번 결정은 "누가 점수를 정하는가"를 바꾸지 않는다.

## 알려진 한계

- OpenAI가 최종 점수를 결정한 기록은 `raw_value`가 있어도 `score`가 그로부터 정확히 재현되지
  않는다. `raw_value`는 항상 1차 규칙 기반 값이라는 점을 소비하는 쪽(분석 도구, 향후 관리자
  화면)이 알고 있어야 한다.
- REDNESS·TROUBLE·PIGMENTATION의 `confidence`는 당분간 `NULL`로 남는다.

## 결과

- `ai-server/app/schema.py` — `RawMeasurements` 모델 신설, `AnalysisResult`에 `raw`·
  `algorithm_version`·`normalization_version` 추가.
- `ai-server/app/metrics.py` — 각 `_metric` 함수가 `(raw, score)`(PORES는 `(raw, score,
  reliability)`) 튜플을 반환하도록 변경. `ALGORITHM_VERSION`·`NORMALIZATION_VERSION` 상수 추가.
- `ai-server/app/vision.py` — `refine()`이 `raw`·버전 필드를 1차 결과에서 그대로 옮긴다.
- `backend`의 `SkinAnalysisResult`·`LocalVisionSkinAnalysisClient`·`MockSkinAnalysisClient`·
  `SkinMetric`·`SkinRecordWriter` 갱신 — 상세는 `docs/STATUS.md` 참고.
- `docs/ERD.md` 7장 SkinMetric — 4개 컬럼 추가.
- `docs/기능명세서.md` F-SKIN-04 — 원시 측정값 저장 규칙 추가.
