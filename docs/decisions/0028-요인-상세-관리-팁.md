# 0028. 요인 상세 관리 팁 — ai-server 단건 생성 + 실패 시 null 폴백

- 상태: **수락**
- 날짜: 2026-08-17
- 담당: B
- 관련: [ADR 0013](0013-요인-상세-응답-구성.md) · [ADR 0022](0022-openai-비전-2단계-점수-확정.md) · [ADR 0025](0025-제품-추천-AI-코멘트.md) · [ADR 0027](0027-클라이언트-파싱-제거-구조화-필드.md) · F-REPORT-03 · REPORT-02

## 맥락

Figma S-20(요인 상세) 최종본에 "💡 관리 팁" 카드가 있다(node `281:917`).

> 레티놀은 처음엔 피부 장벽을 약화시킬 수 있어요. 주 2~3회로 줄이거나, 보습제를 함께 쓰는
> 버퍼링 방식을 시도해 보세요.

프론트엔드가 정확히 진단했듯, 이건 **REPORT-02 응답의 어떤 필드로도 계산·파싱해 만들 수 없는
순수 신규 텍스트**다. 성분별 일반 지식과 사용자 패턴이 섞인 조언 문장이라, 프론트가
하드코딩하면 잘못된 성분에 엉뚱한 조언이 붙는다. 그래서 프론트는 섹션 자체를 넣지 않고
백엔드 필드 추가를 요청했다.

ADR 0025가 같은 성격의 문제(제품 추천 AI 코멘트)를 이미 풀어 두었다 — ai-server가 생성하고
실패하면 `null`로 폴백한다.

## 결정

**관리 팁 생성을 ai-server의 신규 엔드포인트(`POST /insight-tips`)로 위임하고, 생성 실패는
상세 조회 응답을 막지 않는다.** ADR 0025의 구조를 그대로 따른다.

```
ReportService.getInsightDetail()
  저장된 인사이트로 상세 응답 조립 (판정·수치 확정)
    → InsightTipClient.generateTip(근거)   ai-server 1회 호출
         ├ 성공 → tip 채움
         └ 실패/타임아웃 → Optional.empty() → tip = null
```

세부 설계:

- **호출 위치**: ai-server(`app/insight_tip.py`)에 신설. ADR 0022가 정한 "OpenAI는 ai-server
  안에서만" 원칙을 따른다.
- **단건 호출이다.** ADR 0025가 배치인 이유는 추천 목록이 제품 N개이기 때문이다. 요인 상세는
  화면당 인사이트 하나라 배치할 대상이 없다.
- **AI에 넘기는 것은 근거뿐이다.** `title`(성분/요인) · `metric` · `summary` · `confidence` ·
  `lag_days` · `average_delta`를 보낸다. 시스템 프롬프트가 "주어진 근거 밖의 수치를 새로
  지어내지 마라"와 "confidence가 OBSERVING이면 단정하지 말고 관찰을 권하는 어조로 써라"를
  명시한다 — **BR 2("확정되지 않은 패턴에 단정하지 않는다")를 프롬프트 층까지 끌고 내려간다.**
  판정 자체는 Spring이 확정한 상태이고 AI는 그것을 바꾸지 않는다.
- **AI에 넘기는 근거는 `impact` 문구와 같은 기준으로 거른다(2026-08-17 실서버 검증에서 보강).**
  확정되지 않은 패턴(OBSERVING)의 시차·변화량은 `ReportService.firstUsageDelta()`가 이미
  `impact`에서 걸러내고 있으므로, 팁에도 넘기지 않는다. 넘기면 AI가 그 부호를 읽어 "악화됐다"고
  단정해, **화면은 "확인 중"인데 팁만 단정하는 모순**이 생긴다. 거르는 기준을 두 곳에 두지 않고
  `firstUsageDelta()` 하나로 통일한다.
- **근거는 단어가 아니라 관계로 서술한다(2026-08-17 E2E 검증에서 보강).** `요인: 판테놀` /
  `지표: 트러블`처럼 단어만 나열하면 모델이 성분 일반 지식으로 좋고 나쁨을 채워 넣는다.
  `'판테놀'이(가) 트러블 지표에 영향을 주는지 관찰 중`으로 관계를 서술하고, **변화량 부호의
  의미(지표값은 높을수록 증상이 심하므로 양수=악화, 음수=완화)를 풀어서 함께 보낸다.**
  변화량이 없으면 "방향을 추정하지 말고 기록을 더 쌓도록 안내해라"를 명시한다 — 수치를
  지어내지 않는 것만으로는 부족하고, **인과 방향을 지어내는 것도 BR 2 위반이다.**
- **실패 처리**: `InsightTipClient`는 호출 실패를 예외로 전파하지 않고 `Optional.empty()`로
  흡수한다. ai-server는 OpenAI 실패 시 502 + `TIP_UNAVAILABLE`로 응답하고 Spring이
  `RestClientException`으로 잡는다. 팁이 없어도 그래프·이벤트라는 상세 화면의 핵심은
  성립하므로, 팁 실패가 상세 조회를 막아서는 안 된다.
- **타임아웃**: `ProductCommentClient`와 같은 값(connect 5s · read 15s)을 쓴다. 같은
  ai-server를 호출한다.

## 근거

1. **계산으로 만들 수 없는 값이라 AI가 맞는 자리다.** ADR 0027이 추가한 `delta`·`summary`·
   `tags`는 모두 이미 있는 값의 노출이라 규칙으로 정확히 만들 수 있었다. 관리 팁은 성격이
   다르다 — 저장된 데이터에 답이 없다.
2. **AI가 틀려도 손해가 작은 자리다.** ADR 0027이 `tags`에 AI를 쓰지 않기로 한 것과 대비된다.
   `tags`는 짧은 단정문이라 오류가 사실오류로 노출되지만, 팁은 권유 문장이고 nullable이라
   없으면 섹션이 사라질 뿐이다.
3. **기존 폴백 패턴(ADR 0022 · 0025)을 재사용한다.** 새 실패 정책을 만들지 않는다.

## 대안 검토

- **성분별 팁을 DB에 미리 채워 넣기**: 기각(현재는). 성분 마스터에 팁 컬럼을 두면 AI 없이
  결정적으로 동작하지만, 성분 수만큼 문안을 사람이 작성해야 하고 사용자 패턴(시차·변화량)을
  반영할 수 없어 Figma가 보여주는 개인화 수준에 못 미친다. 팁 품질이 문제가 되면 재검토한다.
- **프론트엔드 하드코딩**: 기각. 프론트가 요청서에서 스스로 배제한 안이다 — 잘못된 성분에
  엉뚱한 조언이 붙는다.
- **`summary`에 팁을 합쳐 한 필드로**: 기각. `summary`는 저장된 분석 결과이고 팁은 AI 생성물이라
  실패 시 거동이 다르다. 합치면 AI 실패가 분석 요약까지 날린다.
- **REPORT-01 인사이트 카드에도 팁 달기**: 기각(범위 밖). 카드는 목록이라 N번 호출이 되고,
  Figma도 상세 화면에만 팁을 그린다.

## 알려진 한계 (의도적으로 받아들인 트레이드오프)

- 상세 화면 진입마다 OpenAI를 호출하므로 캐싱 없이는 요청마다 지연·비용이 발생한다.
  ADR 0025가 남긴 것과 같은 한계이며, 같이 재검토한다.
- `insightId`가 영속 식별자가 아니라(ADR 0013) 같은 인사이트라도 재생성되면 팁이 다시
  생성된다 — 캐시 키로 삼을 안정적 식별자가 없다.
- 팁 문안의 의학적 타당성은 프롬프트 제약(진단·치료 표현 금지)에만 의존한다.
- **프롬프트 준수도는 모델에 따라 다르다.** 2026-08-17 E2E 검증은 `gpt-4o-mini`(`.env`의
  `OPENAI_MODEL`)로 했다. 코드 기본값은 `gpt-4o`이므로 실제로 쓰는 모델을 바꾸면 검증을 다시
  해야 한다. 검증 절차와 발견 사항은 `docs/STATUS.md` 2.19절에 있다.

## 결과

- `ai-server/app/schema.py`에 `InsightTipRequest`/`InsightTipResponse` 추가.
- `ai-server/app/insight_tip.py` 신설 — `product_comment.py`와 같은 OpenAI 클라이언트 패턴.
- `ai-server/app/main.py`에 `POST /insight-tips` 추가, 실패 시 502 + `TIP_UNAVAILABLE`.
- `backend`에 `InsightTipClient`(`domain/analysis/client`) 신설 — 기존
  `app.skin.analysis.local-vision.base-url`을 재사용해 같은 ai-server를 가리킨다.
- `ReportInsightDetailResponse`에 `tip`(nullable) 추가.
- `ReportService`가 `InsightTipClient`를 주입받고 `getInsightDetail`이 팁을 채운다.
