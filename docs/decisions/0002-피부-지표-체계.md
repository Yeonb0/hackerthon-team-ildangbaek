# 0002. 피부 지표 체계 — 4종 확정

- 상태: **수락**
- 날짜: 2026-08-08 · 수락: 2026-08-08 (팀 확정 — 트러블 · 홍조 · 모공 · 색소잡티)
- 담당: B(윤진)
- 관련: PRD 14장 TBD-11, F-SKIN-04, `docs/ERD.md` 7장

## 맥락

**피부 지표 종류가 문서와 코드에서 서로 다르다.** 결정 시점(2026-08-08) 저장소 상태 기준:

| 출처 | 지표 |
| --- | --- |
| `SkinMetricType.java` (구현) | `TROUBLE` · `REDNESS` · `MOISTURE_OIL` — **3종** |
| `docs/ERD.md` 7장 | `TROUBLE` · `REDNESS` · `MOISTURE_OIL` — **3종** |
| `docs/api_명세서.md` SKIN-01 응답 | `trouble` · `redness` · `pores` · `pigmentation` — **4종** |
| `docs/api_명세서.md` REPORT-01 `metric` | `TROUBLE` / `REDNESS` / `PORES` / `PIGMENTATION` — **4종** |
| `README.md` 소개 문구 | 트러블 · 홍조 · 유수분 — **3종** (이하 결정에 따라 수정됨) |
| `docs/목업 데이터 구조 정의서.md` `metricType` | `TROUBLE` `REDNESS` `MOISTURE_OIL` — **3종** (이하 결정에 따라 수정됨) |

`SkinMetricType.java`의 주석도 이 불일치를 이미 인지하고 TBD-11 해결 후 값 구성을 다시 맞춰야 한다고 적어두었다.

이 불일치는 방치할 수 없다. `SkinMetric`은 `(skin_record_id, metric_type)` 유니크 제약을 가진 **저장 스키마**이고,
동시에 SKIN-01 응답 · REPORT-01 그래프 · `AnalysisInsight.metric_type` · 리포트 지표 필터가 모두 이 enum을
공유한다. 기록이 쌓이기 시작한 뒤에 바꾸면 이미 저장된 지표 데이터의 마이그레이션이 필요해진다.

## 결정

**API 명세 기준 4종으로 통일한다. 트러블 · 홍조 · 모공 · 색소잡티.**

```
TROUBLE · REDNESS · PORES · PIGMENTATION
```

`MOISTURE_OIL`(유수분)은 지표 집합에서 **제외**한다.

반영 완료:
- `SkinMetricType.java` — 값 교체
- `docs/ERD.md` 7장 — `metric_type` 값 갱신
- `docs/목업 데이터 구조 정의서.md` — `metricType` 값 갱신
- `README.md` — 소개 문구의 "유수분"을 "모공 · 색소잡티"로 수정
- `backend/README.md` — 「알려진 미확정 사항」에서 이 항목 제거, 확정 사실 명시

## 근거

1. **API 명세가 더 하위 계층까지 확정되어 있다.** 4종은 SKIN-01 응답 JSON, REPORT-01의 `metric` 쿼리
   파라미터, S-18·S-19 화면 구성에 이미 반영되어 있다. 3종으로 맞추려면 응답 스키마와 화면 양쪽을 되돌려야 한다.
2. **`MOISTURE_OIL`은 사진 한 장으로 판정하기에 신뢰도가 가장 낮은 지표다.** 유수분은 조명·촬영 직전 세안 여부에
   크게 좌우된다. 반면 `PORES`·`PIGMENTATION`은 시각적으로 관찰 가능하다. 「데이터가 부족하면 임의로 판단하지
   않는다」는 제품 원칙(F-ANALYSIS-04, F-CHECK-03)과 정합적이다.
3. **지금이 가장 싼 시점이다.** 서비스 계층이 아직 하나도 구현되지 않았고 `skin_metrics`에 실데이터가 없다.

## 남은 과제 (이 ADR의 범위 밖)

- **AI 분석 목업/모델이 4종을 실제로 산출할 수 있는가.** 목업 단계에서는 문제없으나(ADR 0003), 실제 모델
  연동 시 `PORES`·`PIGMENTATION` 산출이 불가능하면 이 결정을 대체하는 새 ADR이 필요하다.
- `AnalysisInsight.metricType`은 `SkinMetricType`을 그대로 참조하므로 별도 변경 없이 4종을 지원한다.

## 결과

- `SkinMetric` 저장 시 기록 1건당 4행이 생성된다.
- REPORT-01의 `metric` 기본값은 `TROUBLE`을 유지한다.
- SKIN-01의 `totalScore`는 4개 지표의 대표값으로 산출한다. **산출식은 이 ADR의 범위가 아니며 별도로 정한다.**
