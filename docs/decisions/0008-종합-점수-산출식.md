# 0008. 종합 점수 산출식 — 지표 4종 단순 평균

- 상태: **수락**
- 날짜: 2026-08-08
- 담당: B
- 관련: ADR 0002(지표 4종 확정), SKIN-01 `totalScore`, F-SKIN-04

## 맥락

ADR 0002가 피부 지표를 4종(트러블 · 홍조 · 모공 · 색소잡티)으로 확정하면서 마지막 문단에 이렇게 남겼다.

> SKIN-01의 `totalScore`는 4개 지표의 대표값으로 산출한다. **산출식은 이 ADR의 범위가 아니며 별도로 정한다.**

`totalScore`는 S-18에서 가장 크게 노출되는 숫자이고 리포트의 추이 그래프에도 쓰인다. 구현하려면 확정이 필요하다.

## 결정

**4개 지표의 단순 평균. 반올림한 0~100 정수.**

```
totalScore = round((trouble + redness + pores + pigmentation) / 4)
```

**서비스 계층에서 계산한다.** 분석 클라이언트가 아니다.

## 근거

1. **가중치를 둘 근거가 없다.** 어떤 지표가 사용자의 체감 피부 상태에 더 크게 기여하는지는 데이터로
   확인된 바 없다. 근거 없는 가중치는 **"데이터가 부족하면 임의로 판단하지 않는다"**는 제품 원칙
   (F-ANALYSIS-04 · F-CHECK-03)과 정면으로 어긋난다.
2. **설명 가능하다.** 사용자가 "왜 이 점수인가"를 물으면 네 지표의 평균이라고 답할 수 있다.
   가중 평균은 가중치의 근거를 다시 설명해야 하는데, 지금은 설명할 근거가 없다.
3. **바꾸기 쉽다.** 계산이 서비스 계층 메서드 하나에 있다. 데이터가 쌓여 가중치 근거가 생기면
   그때 새 ADR로 대체한다.

## 왜 분석 클라이언트가 아니라 서비스인가

`SkinAnalysisClient`가 `totalScore`까지 반환하게 하면, 실제 AI 서버로 전환할 때 **산출식이 외부 응답에
종속된다.** 외부 서버가 제 나름의 종합 점수를 주면 우리 산출식과 달라지고, 그때부터 점수의 의미가
연동 시점을 기준으로 갈린다. 지표 4종만 받아 종합 점수는 항상 우리가 계산하면 이 문제가 없다.

## 결과

- `SkinAnalysisResult`는 지표별 점수만 담는다. `totalScore` 필드는 없다.
- 저장은 `SkinRecord.overall_score`(`DECIMAL(5,2)`)에 하되 응답은 정수로 내려간다.
- 실연동 후에도 산출식은 그대로 유지된다.
