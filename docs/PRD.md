# PRD

(Product Requirements Document)

# 1. 프로젝트 개요

## 1.1 프로젝트명

**미정**

> 매일의 제품 사용과 피부 상태를 기록하여 개인 맞춤 피부 프로파일을 생성하는 피부 관리 서비스
> 

## 1.2 한 줄 소개

> 사용자의 피부 상태, 사용 제품, 성분, 환경 정보를 지속적으로 연결해 개인화된 피부 분석과 제품 선택 근거를 제공하는 피부 관리 서비스
> 

## 1.3 서비스 개요

본 서비스는 사용자가 자신의 피부 상태와 사용한 화장품을 꾸준히 기록할 수 있도록 지원하고, 누적된 데이터를 분석하여 다음과 같은 정보를 제공한다.

- 피부 상태 변화
- 사용 제품과 피부 변화의 연관 패턴
- 사용자에게 잘 맞는 성분과 주의가 필요한 성분
- 자외선 등 환경 요인이 피부 상태에 미치는 영향
- 구매를 고려 중인 제품의 개인화 위험도
- 개인 맞춤 피부 리포트

서비스는 단순히 화장품의 일반적인 성분 정보를 제공하는 데 그치지 않고, 사용자의 실제 제품 사용 기록과 피부 변화를 기반으로 **개인별 성분 반응 프로파일**을 생성하는 것을 목표로 한다.

# 2. 배경 및 문제 정의

## 2.1 사용자 문제

피부 관리에 관심이 있는 사용자는 SNS, 영상 콘텐츠, 제품 리뷰, 성분 분석 서비스 등을 참고하여 화장품을 구매한다.

그러나 제품에 대한 일반적인 정보만으로는 다음 질문에 답하기 어렵다.

> “이 제품이나 성분이 실제로 내 피부에 맞는가?”
> 

피부 상태는 제품뿐 아니라 다음과 같은 여러 요인의 영향을 함께 받는다.

- 여러 제품의 동시 사용
- 제품을 사용한 시점과 피부 반응이 나타나는 시점의 차이
- 자외선 등 환경 조건
- 사용자의 피부 타입
- 호르몬 및 생리 관련 상태
- 생활 패턴

따라서 사용자는 피부 상태가 나빠져도 어떤 제품이나 성분이 원인인지 판단하기 어렵고, 효과가 있었던 제품도 정확한 근거 없이 기억에 의존하게 된다.

---

## 2.2 기존 서비스의 한계

기존 성분 분석 및 화장품 정보 서비스는 주로 다음 정보를 제공한다.

- 일반적인 성분 기능
- 특정 피부 유형에 대한 주의 정보
- 다른 사용자의 리뷰
- 제품별 평점과 추천

하지만 같은 성분도 사용자에 따라 반응이 다를 수 있으며, 일반적인 성분 평가가 사용자의 실제 피부 반응과 일치하지 않을 수 있다.

또한 제품 정보, 피부 사진, 환경 정보가 서로 분리되어 관리되는 경우가 많아 사용자가 피부 변화의 원인을 스스로 추적해야 한다.

---

## 2.3 문제 정의문

> 여러 화장품을 사용해도 자신의 피부에 어떤 제품과 성분이 맞는지 판단할 개인 기준이 없는 사용자는 구매 실패와 피부 트러블을 반복한다.
> 
> 
> 본 서비스는 사용자의 제품 사용 기록, 피부 사진 분석 결과, 성분 정보, 환경 정보를 연결하여 개인별 피부 반응 패턴을 축적하고, 이를 기반으로 개인 성분 프로파일과 피부 관리 인사이트를 제공한다.
>

# 3. 서비스 목표

## 3.1 사용자 목표

사용자는 서비스를 통해 다음을 수행할 수 있어야 한다.

- 자신의 기본 피부 특성을 등록한다.
- 자주 사용하는 제품과 루틴을 저장한다.
- 당일 사용한 화장품을 간단하게 기록한다.
- 얼굴 사진을 통해 피부 상태를 기록한다.
- 이전 피부 상태와 오늘의 변화를 비교한다.
- 장기간 피부 변화 추이를 확인한다.
- 자신에게 잘 맞는 성분과 주의 성분을 확인한다.
- 새로운 제품을 구매하기 전에 개인화된 위험도를 확인한다.
- 환경 조건에 맞는 피부 관리 우선순위를 확인한다.

---

## 3.2 서비스 목표

서비스는 다음 데이터를 지속적으로 축적하고 연결해야 한다.

- 사용자 기본 프로필
- 피부 타입
- 호르몬 및 생리 관련 정보
- 수면·기상 시간
- 사용자가 저장한 제품 및 루틴
- 날짜별 제품 사용 기록
- 날짜별 피부 분석 결과
- 제품별 성분 정보
- 날짜별 날씨 및 자외선 정보
- 성분과 피부 변화 사이의 연관 패턴

이를 기반으로 서비스는 다음 결과를 제공한다.

- 피부 상태 비교 결과
- 성분 기반 피부 인사이트
- 환경 기반 피부 인사이트
- 개인 성분 프로파일
- 프로파일 완성도
- 구매 전 제품 위험도

---

# 4. 핵심 가치 제안

## 4.1 개인 기록 기반 분석

서비스는 일반적인 성분 평가가 아니라 사용자가 실제로 사용한 제품과 피부 상태 기록을 기반으로 분석한다.

<aside>
📎

제품 사용
+
제품에 포함된 성분
+
이후 피부 변화
=
개인별 성분 반응 데이터

</aside>

---

## 4.2 기록이 쌓일수록 강화되는 개인화

처음에는 판단할 데이터가 부족할 수 있지만, 사용자가 기록을 지속할수록 성분별 분석 근거와 프로파일 완성도가 증가한다.

개인 성분 프로파일은 다음 상태를 제공한다.

- 잘 맞음
- 지켜보는 중
- 주의 필요

데이터가 부족한 성분을 임의로 긍정 또는 부정으로 판단하지 않는 것을 원칙으로 한다.

---

## 4.3 피부 변화 원인 탐색

서비스는 제품을 사용한 날과 피부 변화가 나타난 날을 단순히 같은 날짜로만 비교하지 않는다.

제품 성분 사용 이후 일정 시간이 지난 뒤 나타나는 피부 변화를 추적하여 반복되는 패턴을 탐색한다.

다만 MVP에서 제공하는 결과는 **의학적 인과관계의 확정이 아닌 기록 기반 연관 패턴**으로 정의한다.

---

## 4.4 환경을 반영한 피부 관리

낮 홈에서는 사용자 위치를 기준으로 기온, 날씨, 자외선, 습도 등의 환경 정보를 보여주고, 사용자가 등록한 제품 중 환경 조건과 관련된 제품의 우선순위를 안내한다. 와이어프레임에는 자외선 지수가 높은 날 자외선 차단제를 우선 표시하고, 실내 건조에 따라 히알루론산 세럼을 안내하는 흐름이 포함되어 있다.

환경 정보는 피부 리포트의 환경 기반 인사이트에도 활용한다.

---

## 4.5 구매 전 의사결정 지원

사용자는 구매를 고려 중인 제품을 검색하거나 스캔하고, 자신의 성분 프로파일과 제품 성분을 비교한 결과를 확인할 수 있다.

서비스는 단순히 위험도만 제공하지 않고 다음 근거를 함께 제공한다.

- 주의가 필요한 성분
- 사용자 과거 반응
- 잘 맞았던 성분
- 데이터가 부족한 성분

와이어프레임에서도 제품 전체 위험도와 함께 향료, 에탄올, 글리세린, 나이아신아마이드별 개인화 근거가 제공된다.

# 5. 타깃 사용자

## 5.1 Primary Target

다양한 화장품을 사용하지만 자신에게 맞는 제품과 성분을 판단하기 어려운 20대 사용자

### 주요 특징

- 피부 트러블이나 홍조 등 피부 변화 경험
- SNS, 리뷰, 콘텐츠 기반 제품 구매
- 여러 제품을 동시에 사용하는 경향
- 화장품 성분에 대한 전문 지식 부족
- 제품 구매 실패를 줄이고 싶은 니즈
- 복잡한 입력이 많은 앱은 지속 사용하기 어려움

---

## 5.2 Secondary Target

꾸준히 피부를 관리하고 있지만 기록을 분석 결과로 연결하지 못하는 사용자

### 주요 특징

- 피부 사진이나 사용 제품을 주기적으로 기록
- 화장품 성분과 피부 변화에 관심
- 피부 리포트와 데이터 시각화 선호
- 환경 조건과 피부 변화의 관계를 알고 싶어 함
- 제품 구매 전 구체적인 판단 근거를 원함

# 6. 페르소나

## 6.1 페르소나 A

### “소비만 반복하는 예민 피부 초년생”

| 항목 | 내용 |
| --- | --- |
| 이름 | 김하은(가상) |
| 나이 | 23세 |
| 직업 | 대학생 4학년 / 취업 준비 중 |
| 거주 | 1인 가구 |
| IT 활용 성향 | 간단한 앱 중심 사용, 복잡한 UI와 긴 설정 과정에서 쉽게 이탈 |

### 상황

하은은 피부 트러블을 줄이기 위해 SNS와 영상 콘텐츠에서 추천하는 토너, 세럼, 크림을 반복적으로 구매해 왔다.

하지만 같은 제품을 사용해도 피부가 좋아지는 날과 나빠지는 날이 있고, 여러 제품을 함께 사용하기 때문에 원인을 구분하기 어렵다.

기존 성분 분석 앱도 사용해봤지만 일반적인 주의 정보가 자신의 실제 경험과 항상 일치하지 않아 신뢰가 낮아졌다.

### 핵심 페인포인트

- 자신에게 어떤 성분이 맞는지 확신이 없음
- 제품 구매 실패와 재구매 반복
- 일반적인 성분 정보가 자신의 이야기처럼 느껴지지 않음
- 트러블 원인이 제품인지 환경이나 컨디션인지 판단하기 어려움
- 기록 과정이 길면 사용을 중단함

### 목표

- 제품 구매 전에 자신의 피부에 맞을 가능성을 확인
- 트러블 유발 가능성이 있는 제품 구매 감소
- 최소한의 행동으로 피부 기록 지속
- 과거 제품 사용과 피부 변화를 쉽게 확인

### 핵심 요구사항

- 저장 제품 및 루틴을 이용한 빠른 기록
- 스캔 또는 검색을 통한 제품 등록
- 피부 촬영 과정 단순화
- 명확하고 짧은 분석 결과
- 기록 유도 및 진행 상태 제공

서연은 기초 루틴과 자외선 차단을 꾸준히 실천하고, 피부 상태도 주기적으로 확인한다.

하지만 제품을 교체하거나 날씨가 달라진 뒤 피부 상태가 변해도 제품, 성분, 환경 중 어떤 요인이 영향을 주었는지 객관적으로 판단하기 어렵다.

여러 앱에 기록이 분산되어 있고, 기록을 해도 실제 행동으로 이어지는 구체적인 분석 결과가 부족하다고 느낀다.

### 핵심 페인포인트

- 피부 변화 원인을 객관적으로 분석하기 어려움
- 제품과 환경 데이터가 분리되어 있음
- 기록은 남지만 피부 관리 의사결정으로 이어지지 않음
- 장기적인 변화와 반복 패턴 확인이 어려움

### 목표

- 피부 변화의 원인을 데이터로 확인
- 장기적인 피부 추이와 주요 이벤트 비교
- 자신만의 성분 반응 프로파일 구축
- 새 제품 구매 시 과거 데이터 기반 판단
- 환경 조건에 맞는 피부 관리 수행

### 핵심 요구사항

- 7일·30일 피부 트렌드
- 성분 및 환경 기반 인사이트
- 상세 요인과 관련 이벤트
- 프로파일 완성도
- 구매 전 개인화 위험도

# 7. 온보딩 및 초기 프로필

## 7.1 목적

개인화 분석과 사용자 경험 설정에 필요한 초기 정보를 입력받는다.

온보딩은 단순한 계정 생성 과정이 아니라 다음 기능의 기반 데이터를 구성하는 단계이다.

- 개인 피부 프로필
- 생활 패턴
- 호르몬 관련 정보
- 피부 타입

## 밤 홈

- 현재 시각

# 8.2 기록 허브

기록 허브는 사용자가 날짜별 기록 상태를 확인하고 제품 기록 또는 피부 기록을 시작하는 중심 화면이다.

주요 기능은 다음과 같다.

- 월간 캘린더 조회
- 날짜별 제품 기록 상태
- 날짜별 피부 기록 상태
- 오늘 제품 기록 시작 또는 결과 조회
- 오늘 피부 기록 시작 또는 결과 조회
- 기간별 기록 횟수
- 피부 분석 완료 횟수

제품과 피부 기록을 모두 완료하면 완료 메시지와 오늘의 기록 결과 요약을 제공한다.

---

# 8.3 제품 기록

제품 기록은 다음 진입 방식을 하나의 화면에서 제공한다.

- 저장된 제품 선택
- 저장된 모닝·나이트 루틴 바로 기록
- 제품명 검색
- 바코드 또는 상품 사진 스캔
- 신규 제품 추가

제품을 선택하면 제품명, 카테고리, 전체 성분 개수, 주요 성분을 확인한 후 기록을 확정한다.

최초 기록한 제품은 사용자 저장 제품 목록에 추가하고, 이후에는 재검색이나 재스캔 없이 사용할 수 있게 한다.

와이어프레임에는 저장 루틴, 저장 제품, 검색, 추가 및 바로 기록 기능이 함께 배치되어 있다.

# 8.4 피부 기록

피부 기록은 다음 흐름으로 진행한다.

<aside>
📎

촬영 가이드

→ 촬영 결과 확인

- 트러블
- 홍조

- 색소 침착

화면에는 종합 피부 점수와 이전 기록 대비 변화도 함께 제공한다.

첫 기록은 비교 대상이 없으므로 기준 데이터로 저장한다.

# 8.5 개인화 분석

개인화 분석은 사용자에게 직접 노출되는 단일 화면이 아니라, 제품 기록과 피부 분석 결과가 저장된 후 실행되는 분석 파이프라인이다.

주요 과정은 다음과 같다.

<aside>
📎

제품 사용 기록 확인

→ 제품 성분 단위 사용 이력 생성

→ 사용 후 1~7일 피부 변화 추적

→ 반복 패턴 탐색

→ 자외선 등 환경 요인 검토

→ 성분별 반응 상태 갱신

→ 프로파일 완성도 계산

</aside>

분석 결과는 다음 기능에서 재사용한다.

- 피부 리포트
- 마이페이지 성분 프로파일
- 구매 전 제품 위험도

# 8.6 구매 전 확인

구매 전 확인에서는 제품 기록 기능의 검색 및 스캔 기능을 재사용한다.

다만 조회한 제품을 실제 사용 기록으로 저장하지 않는다.

처리 흐름은 다음과 같다.

<aside>
📎

구매 고려 제품 검색 또는 스캔

→ 제품 성분 조회

→ 개인 성분 프로파일과 비교

→ 주의·맞음·데이터 부족 성분 분류

→ 제품 전체 위험도 산출

→ 근거와 함께 결과 표시

</aside>

위험도 결과는 낮음, 보통, 높음으로 구분한다.

# 8.7 피부 리포트

피부 리포트는 다음 정보를 제공한다.

- 피부 지표별 그래프

## 9.1 인증

사용자는 지원되는 로그인 수단을 통해 자신의 계정과 누적 기록에 접근한다.

신규 사용자는 로그인 후 온보딩으로 이동하고, 기존 사용자는 온보딩 완료 여부에 따라 홈 또는 마지막 미완료 단계로 이동한다.

### 주요 요구사항

- 지원 로그인 수단을 통한 사용자 식별
- 신규 사용자 계정 생성
- 기존 사용자 데이터 복원
- 인증 상태 유지 및 자동 로그인
- 로그아웃 후 보호 기능 접근 차단
- 로그아웃 이후에도 서버 기록 유지

### 논의 필요

와이어프레임에는 카카오, 구글과 함께 이메일 회원가입·로그인 진입점이 존재한다.

따라서 이메일 로그인을 MVP에 포함할지 확정해야 한다.

## 9.2 온보딩

온보딩은 개인화 분석과 사용자 경험 설정에 필요한 초기 정보를 입력받는 과정이다.

### 주요 요구사항

- 이름, 나이, 성별 입력
- 취침·기상 시간 설정
- 생리 및 호르몬 관련 정보 설정
- 피부 타입 복수 선택
- 알림 권한 및 기록 알림 설정
- 선택 항목 건너뛰기
- 온보딩 완료 상태 저장
- 앱 재실행 시 온보딩 반복 방지

온보딩에서 입력되는 호르몬 정보와 피부 타입은 일반 계정 정보가 아니라 향후 분석 및 추천에 활용하기 위한 개인화 데이터이다.

---

## 9.3 홈

홈은 현재 시간대에 따라 낮과 밤의 콘텐츠를 구분하여 제공한다.

### 낮 홈

- 위치 기반 날씨 정보
- 기온
- 자외선 지수
- 습도
- 사용자 저장 제품 기반 루틴 우선순위
- 추천 이유
- 기록 허브 이동

### 밤 홈

- 당일 기록 상태 확인
- 제품·피부 기록 유도
- 주간 기록 현황
- 나이트 루틴 바로 기록

낮 홈은 환경 조건에 맞는 피부 관리 행동을 제안하고, 밤 홈은 당일 기록 완료를 돕는 역할을 한다.

---

## 9.4 기록 허브

기록 허브는 날짜별 제품 기록과 피부 기록을 관리하는 중심 화면이다.

### 주요 요구사항

- 현재 월 기본 조회
- 이전·다음 월 이동
- 날짜별 제품·피부 기록 상태 표시
- 오늘 기록 상태 표시
- 미완료 기록 시작
- 완료 기록 결과 요약
- 기간별 기록 및 분석 횟수 제공
- 기록 완료 직후 최신 상태 반영

기록이 완료된 경우 제품 요약과 오늘의 피부 분석 점수를 함께 제공한다.

### 논의 필요

기록 통계 기간을 다음 중 하나로 확정해야 한다.

- 주간
- 월간
- 화면별로 주간·월간을 각각 사용

현재 밤 홈은 주간 현황, 기록 허브는 월간 통계를 보여주는 구조이다.

---

## 9.5 제품 기록

제품 기록은 사용자의 제품 사용 이력과 성분 노출 데이터를 축적하는 핵심 입력 기능이다.

### 주요 요구사항

- 저장된 제품 기본 노출
- 최근 사용순 정렬
- 제품명 검색
- 제품 스캔
- 검색 또는 스캔 결과의 성분 확인
- 신규 제품을 저장 제품 목록에 추가
- 모닝·나이트 루틴 조회
- 루틴 단위 바로 기록
- 같은 날짜의 동일 제품 중복 방지
- 제품 기록 완료 후 피부 기록 유도

제품 기록 화면에서는 검색, 저장 루틴, 저장 제품, 바로 기록을 하나의 화면에서 제공한다.

---

## 9.6 피부 기록

피부 기록은 얼굴 사진을 촬영하고 AI 분석 결과를 사용자 기록에 저장하는 과정이다.

### 주요 요구사항

- 촬영 조건 안내
- 얼굴 위치 가이드
- 전면 카메라 사용
- 촬영 이미지 미리보기
- 재촬영
- 이미지 업로드
- 피부 분석
- 오늘 결과 표시
- 이전 기록 대비 변화 표시
- 첫 기록을 기준 데이터로 처리
- 전체 리포트 이동

### 기본 피부 지표

- 트러블
- 홍조
- 유수분

와이어프레임에는 종합 점수와 세 가지 지표의 이전 기록 대비 변화가 표시된다.

---

## 9.7 개인화 분석

개인화 분석은 제품 성분 사용 이력과 피부 상태 변화 사이의 반복 패턴을 탐색하여 사용자 성분 프로파일을 생성하는 시스템 기능이다.

### 주요 요구사항

- 제품 기록에서 성분 사용 이력 구성
- 성분 사용 후 1~7일 피부 변화 추적
- 같은 방향의 변화 반복 여부 확인
- 기록 3일 미만 사용자의 데이터 부족 처리
- 환경 데이터와 함께 분석
- 성분별 맞음·주의·데이터 부족 분류
- 데이터 누적에 따른 상태 재평가
- 프로파일 완성도 계산

### 분석 결과 해석 원칙

MVP의 분석 결과는 의학적 인과관계의 확정이 아니라 다음 수준으로 제공한다.

> 사용자의 기록에서 반복적으로 관찰된 연관 패턴
> 

분석 근거가 부족한 경우 단정적인 표현을 사용하지 않는다.

---

## 9.8 구매 전 확인

사용자는 구매하려는 제품을 검색하거나 스캔하여 자신의 성분 프로파일과 비교할 수 있다.

### 주요 요구사항

- 제품 기록 기능의 검색·스캔 로직 재사용
- 조회 제품을 사용 기록으로 저장하지 않음
- 제품 전체 성분과 개인 프로파일 비교
- 주의 성분 식별
- 맞음·주의·데이터 부족 상태 표시
- 낮음·보통·높음 위험도 제공
- 개인 기록 기반 판단 근거 제공
- 프로파일 부족 상태 안내

위험도 화면에서는 제품 전체 평가뿐 아니라 성분별 개인화 사유를 함께 제공한다.

---

## 9.9 피부 리포트

피부 리포트는 누적된 피부 기록과 분석 결과를 사용자가 이해할 수 있는 형태로 제공한다.

### 주요 요구사항

- 최근 7일 조회
- 최근 30일 조회
- 피부 지표별 추이 그래프
- 성분 기반 인사이트
- 환경 기반 인사이트
- 주요 이벤트 표시
- 요인 상세 화면
- 기록이 없는 날짜를 0점으로 처리하지 않음
- 데이터 부족 시 단정적인 인사이트 미제공

와이어프레임의 상세 리포트에서는 제품 첫 사용, 높은 자외선, 특정 성분 제품 재사용 등의 이벤트를 피부 지표 변화와 연결해 보여준다.

---

## 9.10 마이페이지

마이페이지에서는 사용자의 활동 정보와 개인화 분석 결과를 확인하고 설정을 관리한다.

### 주요 요구사항

- 사용자 이름
- 가입 경과일
- 누적 기록 횟수
- 피부 타입
- 잘 맞는 성분
- 주의 성분
- 프로파일 완성도
- 전체 성분 프로파일 조회
- 위치 설정
- 알림 설정
- 로그아웃

와이어프레임에서는 잘 맞는 성분과 주의 성분, 프로파일 완성도, 위치·알림·로그아웃 메뉴를 함께 제공한다.

# 10. MVP 정의

## 10.1 문제 정의

> 여러 화장품을 사용해도 자신에게 맞는 제품과 성분을 판단할 개인화된 기준이 없는 사용자는 피부 트러블과 구매 실패를 반복한다.
> 
> 
> 본 서비스는 사용자의 제품 사용 기록, 얼굴 사진 기반 피부 분석, 제품 성분, 환경 데이터를 연결하여 개인별 피부 반응 패턴을 축적하고, 이를 기반으로 개인 성분 프로파일과 구매 전 판단 근거를 제공한다.
> 

---

## 10.2 MVP 핵심 가설

> 사용자가 제품 사용 기록과 피부 사진을 꾸준히 남기면, 제품 성분과 피부 상태 변화 사이에서 반복되는 연관 패턴을 탐색할 수 있다.
> 
> 
> 이 기록을 기반으로 생성된 개인 성분 프로파일은 사용자가 새 제품을 선택할 때 일반적인 리뷰보다 개인화된 판단 근거를 제공하며, 기록이 누적될수록 서비스 가치가 증가한다.
> 

---

## 10.3 MVP 핵심 사용자 흐름

```
로그인 및 온보딩
        ↓
홈에서 오늘 환경과 관리 우선순위 확인
        ↓
오늘 사용한 제품 기록
        ↓
얼굴 사진 촬영 및 피부 분석
        ↓
제품 성분과 피부 변화 데이터 축적
        ↓
개인 성분 프로파일 갱신
        ↓
피부 리포트 확인
        ↓
구매 전 제품 위험도 확인
```

---

## 10.4 MVP 핵심 기능

| **기능** | **설명** | **MVP 가치** |
| --- | --- | --- |
| **사용자 인증** | 사용자를 식별하고 누적 기록에 접근 | 개인 데이터 지속성 |
| **초기 프로필** | 기본 정보, 피부 타입, 선택적 생활·호르몬 정보 저장 | 초기 개인화 기반 |
| **환경 기반 홈** | 날씨·자외선과 저장 제품을 기반으로 오늘의 우선순위 제공 | 일상 피부 관리 지원 |
| **제품 기록** | 검색, 스캔, 저장 제품 또는 루틴으로 사용 제품 기록 | 성분 노출 데이터 확보 |
| **피부 기록** | 얼굴 사진 촬영 및 AI 피부 분석 | 피부 변화 데이터 확보 |
| **개인화 분석** | 성분 사용과 피부 변화의 반복 패턴 분석 | 핵심 차별점 |
| **개인 성분 프로파일** | 성분을 맞음·주의·데이터 부족(지켜보는 중)으로 분류 | 개인화 자산 형성 |
| **피부 리포트** | 피부 추이와 성분·환경 인사이트 제공 | 기록 가치 확인 |
| **구매 전 확인** | 새 제품의 성분을 개인 프로파일과 비교 | 구매 실패 감소 |

- 제품 스캔

기능 자체는 유지하되 실제 모델 대신 샘플 데이터나 간이 규칙을 사용할 수 있다.

# 11. 구현 전략 및 품질 기준

## 11.1 해커톤 구현 전략

해커톤에서는 서비스의 전체 사용자 흐름과 개인화 가치 검증에 집중한다.

실제 외부 모델이나 데이터 확보가 어려운 기능은 목업 또는 간이 로직으로 구현할 수 있다.

| **기능** | **권장 구현 방식** |
| --- | --- |
| 소셜 로그인 | 실제 OAuth 또는 테스트 사용자 기반 목업 |
| 이메일 로그인 | 일정에 따라 제외 가능 |
| 제품 검색 | 샘플 제품 데이터베이스 |
| 제품 스캔 | 제한된 샘플 바코드 또는 제품만 인식 |
| AI 피부 분석 | 실제 분석 API 또는 사전에 정의된 샘플 결과 |
| 시간차 분석 | 최근 기록을 대상으로 한 규칙 기반 분석 |
| 환경 요인 보정 | 자외선이 높은 날짜의 신뢰도 조정 등 간이 로직 |
| 개인 성분 프로파일 | 기록 횟수와 변화 방향 기반 규칙 |
| 위험도 계산 | 주의 성분 개수·비율 기반 규칙 |
| 리포트 인사이트 | 분석 결과와 연결된 템플릿 문구 |
| 날씨·자외선 | 실제 API 또는 고정 지역 샘플 데이터 |

### 구현 원칙

- 목업 데이터도 실제 API 응답 형태와 동일하게 구성
- 분석 결과가 고정값이어도 사용자 기록과 연결된 것처럼 일관되게 동작
- 화면만 존재하고 데이터 저장이 되지 않는 기능 최소화
- 사용자에게 실제 AI 또는 의학적 진단으로 오해될 표현 사용 금지

## 11.3 사용성 요구사항

- 제품 기록 방식 선택을 위한 별도 화면을 두지 않는다.
- 저장 제품과 루틴을 우선 노출한다.
- 기존 제품은 재검색이나 재스캔 없이 기록할 수 있어야 한다.
- 피부 촬영 전 조건을 짧고 명확하게 안내한다.
- 기록 완료 상태를 즉시 확인할 수 있어야 한다.
- 데이터가 부족한 경우 오류처럼 보이지 않도록 별도 안내를 제공한다.
- 위험도와 인사이트에는 이해 가능한 이유를 함께 제공한다.
- 선택 입력 항목 때문에 온보딩이 중단되지 않아야 한다.

---

## 11.4 신뢰성 요구사항

- 분석 실패 시 기존 제품 및 피부 기록을 삭제하지 않는다.
- 저장 실패 시 사용자가 입력한 정보를 가능한 한 유지한다.
- 기록 없음과 서버 조회 실패를 구분한다.
- 같은 저장 요청이 반복 전송되지 않도록 한다.
- 동일 날짜와 제품의 의도하지 않은 중복 기록을 방지한다.
- 기록 저장 완료 후 관련 화면의 상태를 최신화한다.
- 외부 환경 API 장애가 앱 전체 장애로 이어지지 않도록 한다.

## 11.5 보안 및 개인정보 요구사항

서비스는 얼굴 이미지, 피부 분석 결과, 호르몬 관련 정보 등 민감할 수 있는 데이터를 처리한다.

### 기본 원칙

- 인증된 사용자만 자신의 데이터에 접근
- 다른 사용자의 기록 접근 차단
- 통신 구간 HTTPS 적용
- 비밀번호 직접 저장 금지
- 인증 토큰의 안전한 저장
- 얼굴 이미지 접근 권한 제한
- 로그에 민감 정보와 인증 정보 기록 금지
- 탈퇴 또는 삭제 요청 시 개인정보 처리 정책 마련

### 민감 데이터

- 얼굴 이미지
- 피부 분석 결과
- 성별 및 나이
- 생리 주기
- 호르몬약 및 주사 정보
- 위치 정보

특히 호르몬 및 얼굴 이미지 데이터는 MVP에서 실제로 필요한 범위를 다시 검토해야 한다.

## 13.2 데이터 최소 수집 원칙

- MVP 분석에 활용하지 않는 정보는 필수 입력으로 받지 않는다.
- 선택 입력 정보는 건너뛰기를 허용한다.
- 호르몬 정보는 실제 분석 반영 여부를 먼저 확정한다.
- 원본 얼굴 이미지 보관이 필요하지 않다면 분석 후 삭제하는 방안을 검토한다.
- 위치는 정밀 좌표 대신 시·구 단위 설정을 사용할 수 있다.

---

## 13.3 분석 결과 표현 원칙

- 질병 진단 또는 치료 효과처럼 표현하지 않는다.
- “원인”보다 “연관 패턴”, “관찰된 변화” 등의 표현을 사용한다.
- 데이터가 부족한 경우 결과를 생성하지 않거나 데이터 부족으로 표시한다.
- 위험도는 의학적 안전성 판정이 아닌 사용자 기록 기반 참고 정보임을 안내한다.
- 사용자의 기록이 수정되거나 삭제되면 분석 결과 재계산 가능성을 고려한다.
